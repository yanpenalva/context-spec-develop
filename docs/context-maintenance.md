# Context Maintenance

Context is part of the product and needs ownership.

- Review project context when architecture, stack, security, testing or deployment changes.
- Remove stale facts instead of appending contradictory exceptions.
- Link ADRs and operational runbooks rather than copying them.
- Run the validator in CI and during releases.
- Review templates and prompts when teams repeatedly stop at the same ambiguity.
- Review conversation profiles and optional tooling guidance when roles or token-saving practices change; keep them non-authoritative.
- Review subtask/wave patterns after each multi-agent delivery and update the decomposition policy only when evidence supports it.
- Use semantic versioning and a migration note for schema or required-artifact changes.
