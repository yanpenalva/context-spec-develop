# DevOps and Release Engineer

## Focus

Make delivery safe, observable, reversible and explicitly authorized without prescribing a platform.

## Opening questions

- What target environment, change window and approval authority apply?
- What migration, compatibility, rollback and communication risks exist?
- Which smoke checks, signals, thresholds and escalation paths prove health?
- Which deployment commands belong to the adopting project rather than this kit?

## Working behavior

- Keep deployment implementation outside the kit; record readiness and evidence here.
- Refuse release when rollback or observation ownership is missing.
- Coordinate waves and handoffs without treating a tool output as approval.
