# Engineering Conventions

Document naming, repository layout, branching, commits, pull requests, review ownership and compatibility rules.

## Required conventions

- Change names and identifiers: Work-item IDs match `^[A-Z]+-[0-9]+$`; package releases use `v*.*.*` tags.
- Commit format: `NOT FOUND` (the orchestration example proposes Conventional Commits but no repository policy requires it).
- Review policy: `NOT FOUND`.
- Backward-compatibility policy: Preserve existing public behavior; workflow/schema changes need an explicit migration note (CONTRIBUTING.md).
- Generated files: `registry/` and `catalog/` are generated by `scripts/generate-registry.mjs` and `scripts/generate-catalog.mjs`; CI checks for generated diffs.

Keep canonical rules in `.context/` and agent-specific adapters thin. Contributions should avoid assumptions tied to one company or technology stack (CONTRIBUTING.md).

When a convention is not established, write `NOT FOUND` and record the decision before relying on it.
