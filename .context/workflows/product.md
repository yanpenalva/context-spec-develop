# Product Workflow

Use this overlay for new capabilities, product improvements and validated experiments.

Select this track during intake only when the request is a new or improved user/operator outcome. A defect or active degradation belongs to Support even when the proposed solution is a feature.

```text
Discovery → Specify → Plan → Preflight Validate → Execute and Test
          → Verify and Review → Release and Deploy → Observe → Learn and Close
```

## Discovery gate

`discovery.md` must identify the user or operator problem, evidence, affected audience, constraints, hypothesis, expected value and measurable success signal. A solution proposal alone is not a discovery.

## Product decisions

- Product owner approves problem, scope and success criteria.
- Engineering owns the technical plan and implementation evidence.
- Design, security, data and operations reviewers are included when the change affects their boundaries.
- Unmeasurable “success” is a discovery gap, not an implementation instruction.

## Required artifacts

`discovery.md`, `spec.md`, `plan.md`, `preflight.md`, `verification.md`, `review.md`, `release.md`, `outcome.md`.
